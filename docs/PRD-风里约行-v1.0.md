# 风里约行 PRD

> **版本**：v1.0  
> **状态**：产品与前端重构基准  
> **产品名**：风里约行  
> **更新时间**：2026-08-27

---

## 1. 产品概述

### 1.1 一句话定义

风里约行帮助用户把任意一段空闲时间，变成一次由自己掌控、可以真实发生的出发。

### 1.2 要解决的问题

用户常常有一点空闲、一点情绪或一个模糊念头，例如：

- 下班后不想直接回家；
- 周日下午想晒晒太阳；
- 想找一个地方安静待一会；
- 想去看展，却不想花力气安排；
- 有一条路线想去，但想先确认是否适合与别人同行。

这些念头通常停留在“想一想”，原因是：

1. 不知道去哪里、怎么安排；
2. 现有路线内容只提供信息，不能自然转化为自己的行动；
3. 想同行时，缺少以具体时间、地点和节奏为基础的低压力机制；
4. 出发结束后，没有一个低负担、私密的方式留下生活轨迹。

### 1.3 产品目标

让用户完成以下最小闭环：

```text
一个念头 / 一段空闲时间
        ↓
找到或生成一条路线
        ↓
采用为自己的计划
        ↓
独自出发，或发起/加入一次同行
        ↓
完成后留下私密记录
```

### 1.4 非目标

风里约行不是：

- 泛内容社区或刷路线的信息流；
- 任意用户之间的陌生人社交产品；
- 自动替用户决定生活、自动替用户报名的代理；
- 打卡、连续签到、惩罚断签的任务工具；
- 公开展示用户所有生活轨迹的社交广场。

## 2. 产品原则

### 2.1 用户始终拥有决定权

- AI 生成路线默认私密；
- 用户决定是否保存、编辑、公开；
- 用户决定独自去还是发起同行；
- 用户决定是否留下记录；
- 用户查看发起人公开主页后，才决定是否加入同行。

### 2.2 路线与行动分离

路线是可参考、可采用的内容；计划才是用户“我要去做这件事”的个人行动副本。

用户编辑自己的计划，不能修改原始路线。

### 2.3 同行服务于一次具体出发

同行邀约必须有具体时间、集合地点、人数和节奏。它不是加好友、关注或陌生人私聊入口。

### 2.4 私密优先

- AI 原始输入默认私密；
- 私人路线默认私密；
- 个人计划默认私密；
- 生活记录默认私密；
- 私聊仅对同一次邀约成员可见。

### 2.5 低压力

产品鼓励“想去就去”，但不制造签到压力、任务压力或社交压力。

## 3. 核心对象与关系

### 3.1 路线方案 Route

**定义**：可被浏览、采用和二次编辑的路线内容。

**来源**：

| 来源 | 说明 | 默认可见性 |
|---|---|---|
| 系统精选 | 平台维护的稳定城市路线 | 公开 |
| 大家发布 | 用户确认公开的地点或路线 | 公开 |
| AI 路线 | 根据用户本次输入生成的路线草稿 | 私密 |

**主要字段**：

- 标题；
- 描述；
- 路线类型：一个地点 / 完整路线；
- 区域；
- 时长；
- 预算；
- 交通/节奏；
- 停留点列表；
- 可见性；
- 来源类型。

**规则**：

- 路线本身不是一次出发；
- 任何人采用路线，都创建自己的计划副本；
- 采用者不会改动来源路线；
- 私密 AI 路线必须经用户明确操作后才能公开。

### 3.2 我的计划 Plan

**定义**：用户采用一条路线后形成的个人执行副本。

**主要字段**：

- 路线快照 `route_snapshot`；
- 来源路线 ID；
- 计划状态；
- 计划出发时间；
- 用户对副本的编辑内容。

**状态机**：

```text
saved（待决定）
  ↓ 安排时间
scheduled（已安排）
  ↓ 开始
active（出发中）
  ↓ 完成
completed（已完成）
```

**规则**：

- `saved`：可以先留着，不要求立即安排；
- `scheduled`：已确定大概出发时间；
- `active`：正在路上；
- `completed`：已完成，可回看并留下记录；
- 计划可独自执行，也可作为邀约基础；
- 计划编辑只影响个人副本。

### 3.3 同行邀约 Invitation

**定义**：基于一个计划发起的一次具体出发。

**创建前置条件**：必须关联一个 Plan；不能从空白状态直接发邀约。

**必须信息**：

- 出发时间；
- 集合地点；
- 最多人数（含发起人）；
- 同行节奏；
- 预算说明；
- 补充说明。

**状态**：

```text
open（正在邀约） → closed（已结束）
```

**规则**：

- 发起人自动占用一个名额；
- 人数上限必须由后端校验；
- 同一路线可产生多次、不同用户的邀约；
- 用户加入前应能查看发起人的公开资料；
- 用户可退出邀请；发起人可结束邀请；
- 邀约结束后不可新增成员。

### 3.4 路线私聊 Conversation

**定义**：仅服务于一次具体邀约的成员沟通。

**规则**：

- 仅已加入该邀约的成员可进入；
- 不提供任意用户间陌生人私信；
- 聊天内容聚焦集合、时间、路线调整和临时变更；
- 邀约结束后聊天记录可回看，但不可再发送；
- 支持举报。

### 3.5 公开同行主页 Public Profile

**定义**：帮助用户在加入某次邀约前做出知情判断的公开资料页。

**可展示字段**：

- 头像；
- 昵称；
- 一句自我介绍；
- 城市；
- 出发节奏；
- 常见可出发时间；
- 最多 6 张介绍照片。

**明确不展示**：

- AI 原始输入；
- 私密路线和私密计划；
- 生活记录；
- 精确住址、工作地点；
- 与本次邀约无关的私人信息。

### 3.6 生活记录 Life Record

**定义**：用户对一次出发、一个感受或一段日常的私密留存。

**字段**：

- 文本内容；
- 心情；
- 可选关联计划 ID；
- 可选关联路线 ID；
- 创建时间。

**规则**：默认仅自己可见，不用于公开动态流。

## 4. 用户与使用场景

### 4.1 目标用户

- 有城市生活空间、愿意把日常过得更有意识的人；
- 不一定追求高频社交，但愿意在合适时与人同行；
- 认可 AI 的辅助价值，但希望保留自己的判断和选择；
- 需要低压力、非任务化的生活安排方式。

### 4.2 核心场景

| 场景 | 用户心态 | 产品应提供的最小帮助 |
|---|---|---|
| 下班后有两小时 | 想出去但没想法 | AI 或精选路线给出可执行第一版 |
| 周末想去一个地方 | 知道想去哪，不知道怎么安排 | 采用路线后形成可编辑计划 |
| 想先留着再说 | 不想被时间约束 | 保存为待决定计划 |
| 想有人同行 | 想有陪伴但不想社交压力 | 基于具体邀约查看条件和发起人主页 |
| 出发结束 | 想留下感受 | 私密生活记录 |

## 5. 信息架构与一级导航

一级导航固定为：

```text
首页 / 路线 / 发布 / 邀约 / 我的
```

### 5.1 首页

**首要问题**：我今天要不要出发？

优先级：

1. 未完成的个人计划；
2. 没有计划时的开始方式：AI 生成 / 路线库；
3. 一条精选路线；
4. 同行邀约摘要；
5. 生活记录入口。

首页不是功能罗列，也不是路线瀑布流。

### 5.2 路线

**首要问题**：哪条路线适合我？

内容：

- 系统精选；
- 大家发布；
- 创建路线入口。

路线详情的唯一主操作：**采用为我的计划**。

### 5.3 发布

**首要问题**：我想创建哪种路线？

两种创建模式：

1. AI 私人路线：默认私密；
2. 公开路线方案：可供别人采用。

发布页不直接创建同行邀约。同行必须从个人计划发起。

### 5.4 邀约

**首要问题**：这一次出发是否适合我加入？

筛选：

- 正在邀约；
- 我加入的。

邀约卡优先显示：

1. 时间；
2. 集合地点；
3. 人数；
4. 节奏与说明；
5. 发起人主页；
6. 加入 / 私聊 / 退出等状态操作。

### 5.5 我的

**首要问题**：我的出发现在进行到哪里？

内容：

- 个人公开主页；
- 我的计划；
- 我的邀约；
- 生活记录入口；
- 资料编辑。

## 6. 核心用户流程

### 6.1 从 AI 开始

```text
首页 / 发布
  ↓ 输入一句想法
AI 生成私密路线
  ↓ 查看路线详情
采用为我的计划
  ↓
待决定 / 安排时间 / 独自出发 / 发起同行
```

### 6.2 从系统路线开始

```text
路线库
  ↓ 查看路线详情
采用为我的计划
  ↓
安排时间
  ↓
开始出发
  ↓
完成并留下私密记录
```

### 6.3 发起同行

```text
个人计划
  ↓ 点击“和别人一起去”
确认路线公开范围（如有必要）
  ↓ 填写时间、集合地、人数、说明
创建邀约
  ↓ 其他用户查看行动条件
  ↓ 查看发起人公开主页
  ↓ 加入邀约
  ↓ 进入仅成员可见的路线私聊
```

### 6.4 加入同行

```text
邀约列表
  ↓ 查看时间 / 集合地 / 节奏 / 人数
  ↓ 查看发起人公开主页
  ↓ 加入邀约
  ↓ 路线私聊
  ↓ 出发 / 邀约结束
  ↓ 私密记录
```

## 7. 页面功能需求

### 7.1 首页

| 模块 | 触发条件 | 内容 | 行为 |
|---|---|---|---|
| 下一次出发 | 有未完成计划 | 状态、标题、时间/说明 | 进入计划详情 |
| 开始方式 | 无计划或常驻次级入口 | AI 生成、路线库 | 进入发布 / 路线 Tab |
| 今日推荐 | 有系统路线 | 标题、区域、时长、预算 | 进入路线详情 |
| 同行摘要 | 有开放邀约 | 时间、人数、路线 | 进入邀约 Tab |
| 生活记录 | 始终存在 | 最近一条/引导文案 | 进入生活记录 |

### 7.2 路线详情

| 模块 | 内容 | 行为 |
|---|---|---|
| 路线信息 | 标题、说明、时长、预算、区域 | 浏览 |
| 采用决策 | 私人副本说明 | 采用为计划 |
| 私密路线公开 | 仅私密路线可见 | 明确公开操作 |
| 路线停留点 | 时间、地点、说明 | 浏览 |
| 已有邀约 | 行动条件、加入/聊天 | 仅作为次级信息 |

### 7.3 计划详情

| 状态 | 主操作 | 次级操作 |
|---|---|---|
| 待决定 | 安排时间 | 编辑、发起同行 |
| 已安排 | 现在出发 | 编辑、发起同行 |
| 出发中 | 完成这次出发 | 留下记录 |
| 已完成 | 写下私密记录 | 回看计划 |

### 7.4 邀约列表

每张邀请卡必须包含：

- 邀约状态；
- 人数；
- 路线标题；
- 时间；
- 集合地；
- 节奏/预算说明；
- 发起人说明；
- 查看发起人主页入口；
- 与身份和状态匹配的操作。

### 7.5 私聊

- 顶部声明：仅本次邀约成员可见；
- 开放邀约：可发送消息；
- 已结束邀约：只读提示，隐藏输入框；
- 举报入口；
- 不伪造“我/对方”消息左右气泡，直到数据层提供可靠的消息发送者 ID。

## 8. UI 与交互规范

### 8.1 设计原则

视觉使用 Apple HIG 的交互原则，但必须遵循微信小程序的容器规范。

- **HIG 借鉴**：清晰层级、可读性、克制的材料深度、状态驱动的主操作；
- **微信小程序约束**：菜单安全区、一级 Tab 数量、二级返回、局部加载反馈、明确错误与结果反馈。

### 8.2 微信小程序规范要求

1. 页面顶部为微信右上角官方菜单预留安全空间；
2. 次级页面提供明确返回；
3. 一级导航固定为 5 项，不在页面中叠加多组复杂 Tab；
4. 加载优先局部反馈，避免不必要的全屏遮罩；
5. 结果提供明确反馈：成功可轻量 Toast，错误要解释原因和解决方式；
6. 底部固定操作与自定义 TabBar 必须预留安全区；
7. 动效仅用于层级进入、按压反馈、状态过渡，不使用持续干扰阅读的装饰性动画。

### 8.3 动效原则

- 页面内容：短暂、低频的分段进入；
- 主计划：可有低对比度的呼吸光晕，突出当前行动；
- 路线图：可有极低频的缩放/光线效果；
- 点击卡片：轻微缩放或颜色变化；
- 不使用无意义的无限跳动、扫光或高频粒子动画；
- 优先使用微信小程序支持的 WXSS 渐变与 CSS 动画；复杂关键帧动画须考虑基础库与渲染引擎兼容性。

## 9. 权限、安全与隐私

### 9.1 前端展示边界

前端不得展示：

- 用户 AI 原始输入；
- 私密路线、私密计划；
- 私密生活记录；
- 精确住址与工作位置；
- 无关用户的联系方式。

### 9.2 后端必须验证的规则

| 场景 | 必须校验 |
|---|---|
| 采用路线 | 创建者身份与个人计划归属 |
| 编辑计划 | 计划属于当前用户 |
| 发布私密路线 | 路线属于当前用户 |
| 创建邀约 | 计划属于当前用户；人数范围合法 |
| 加入邀约 | 邀约开放且未满员 |
| 私聊 | 当前用户为该邀约成员 |
| 关闭邀约 | 当前用户为发起人 |
| 退出邀约 | 当前用户为成员 |
| 举报私聊 | 举报人与目标会话/邀约具备合法关联 |
| 查看公开主页 | 仅返回明确授权的公开字段 |

### 9.3 当前待补齐的后端风险

1. 公开主页查询应与有效邀约或授权范围关联，避免可枚举任意用户资料；
2. 举报接口应校验举报人是否具备目标会话/邀约访问资格；
3. 邀约中展示的发起人资料应明确采用“创建时快照”或“实时公开资料”的一致策略；
4. 会话消息接口应返回稳定的发送者 ID / `is_mine`，再支持标准双侧气泡布局。

## 10. MVP 范围

### 10.1 本期必须具备

- 系统路线浏览；
- 社区公开路线浏览；
- AI 私密路线生成；
- 路线采用为个人计划；
- 计划状态推进与编辑；
- 基于计划发起邀约；
- 邀约加入、退出、结束；
- 发起人公开主页；
- 邀约成员私聊、只读结束态、举报；
- 私密生活记录；
- 个人主页与头像/照片编辑；
- 完整的空、加载、失败和成功反馈。

### 10.2 本期不做

- 陌生人自由私信；
- 关注、粉丝、点赞、排行榜；
- 实时位置共享；
- 自动匹配、自动代替用户报名；
- 连续签到和强制游戏化；
- 公开生活记录动态流；
- 复杂推荐算法承诺。

## 11. 验收标准

### 11.1 产品链路验收

- [ ] 用户能从系统路线采用出一份独立计划；
- [ ] 修改计划不影响来源路线；
- [ ] AI 生成路线默认私密；
- [ ] 用户能明确选择公开路线，而非被自动公开；
- [ ] 邀约必须从计划发起；
- [ ] 加入邀约前能看到时间、集合地、人数、节奏和发起人公开主页；
- [ ] 非成员无法进入私聊；
- [ ] 邀约结束后成员能回看但不能发送；
- [ ] 生活记录默认仅自己可见。

### 11.2 前端验收

- [ ] 每页只存在一个明确主任务；
- [ ] 首页优先呈现“下一次出发”，不做功能堆砌；
- [ ] 路线详情主操作明确为“采用为我的计划”；
- [ ] 计划详情主操作随状态变化；
- [ ] 邀约卡先展示行动条件，再展示社交操作；
- [ ] 各页面具有独立样式文件，不依赖历史全局样式覆盖；
- [ ] 自定义 TabBar 具备安全区、选中状态和清晰主操作；
- [ ] 文字对比度、点击区域、滚动和底部操作不被遮挡；
- [ ] 微信 CI 编译通过；
- [ ] 真机预览逐页验证通过后，才可上传新的体验版/开发版。

## 12. 后续迭代方向

不进入本期 MVP，但可以在闭环稳定后评估：

- 基于用户历史计划与记录的私人路线建议；
- 出发前轻提醒（由用户主动开启）；
- 多城市路线扩展；
- 邀约的申请制与更细的成员管理；
- 行程后的图片/语音私密记录；
- 用户可控的年度/主题回望。

## 13. 版本决策记录

| 决策 | 结论 |
|---|---|
| 产品核心 | 让空闲时间变成真实出发，而非内容消费或社交增长 |
| 路线与计划 | 必须分离；计划是个人执行副本 |
| AI | 先私密草稿，用户决定保存/公开/邀约 |
| 同行 | 仅限基于计划的一次具体行动 |
| 主页 | 同行前的信任界面，不是社交主页 |
| 记录 | 默认私密，不做公开动态 |
| UI | HIG 交互原则 + 微信小程序规范，而非套用任一视觉模板 |
| 发布门禁 | 真机视觉与关键流程验证通过前，不上传体验版/开发版 |
